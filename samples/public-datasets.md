# Public datasets used to test the importer

These files are not stored in the repository because their licenses do not clearly allow redistribution.
Run `samples/fetch-public-datasets.sh` to download them into `samples/public/` (ignored by git), then upload them on the Import page to reproduce the results below.

## 1. Daily campaign data with breakdown rows

- Source: [Lifewitdata/Advertising-Performance-Analytics](https://github.com/Lifewitdata/Advertising-Performance-Analytics), file `data/ads_daily.csv`
- Synthetic (generated by the author), 2025-01-01 to 2025-03-31, 6 campaigns.
- Each campaign and day is split into 12 rows by country, device and audience segment.

Expected result with no manual mapping (`spend_usd`, `revenue_usd` and `campaign_id` are recognized automatically):

| | |
|---|---|
| Rows in file | 6,480 |
| Imported (campaign x day) | 540 |
| Summed into another row of the same campaign and day | 5,938 |
| Rejected | 2 (one row with clicks above impressions, one with negative spend) |

What it exercises: summing of breakdown rows, currency suffix in column names, row-level validation on real-looking noise.

## 2. Totals per ad, no date column

- Source: the Kaggle "Sales Conversion Optimization" data (1,143 Facebook ads), e.g. [Esraarashwan/marketing-campaign-analysis](https://github.com/Esraarashwan/marketing-campaign-analysis), file `data/KAG_conversion_data.csv`.
- The file uses old Mac line endings (only `\r`); the parser reads it correctly.
- It has no date column and **no revenue column**.

Because revenue is a required field, the file cannot be imported as is. With a zero revenue column added and a period chosen,
the importer reproduces the file's totals exactly (spend 58,705.23; impressions 213,434,828; clicks 38,165; approved conversions 1,079),
spread over the chosen days as 3 campaigns x N days.

## What these files taught us

- Real exports are often broken down by country, device or audience, so the same ad and day appears many times. The importer sums those rows and reports how many it merged. A row that is an exact copy of an earlier one is still rejected, so a file pasted twice does not double the numbers.
- Some exports have totals for a whole period. They need a period instead of a date column, and their daily charts are flat by construction.
- Lead-generation and awareness data has no revenue. That is not supported yet.
